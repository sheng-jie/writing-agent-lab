# 写作意图识别策略

## 必须追问的情况

以下情况不能直接输出写作意图，应该继续澄清：

1. 只有宽泛主题，没有目标读者。  
   例如：我想写一篇关于 AI Coding 的文章。
2. 只有主题，没有核心观点。  
   例如：我想写 MCP。
3. 只有技术名词，没有写作目的或发布平台。  
   例如：帮我写一篇关于 Agent 的内容。
4. 用户的目标互相冲突。  
   例如：既要写给小白，又要深入源码实现。
5. 用户要求过大，无法形成单篇文章边界。  
   例如：帮我全面介绍人工智能。

## 不应该机械追问的情况

以下情况可以直接整理写作意图：

1. 用户已经说明目标读者、主题和核心判断。
2. 用户虽然没有完整细节，但写作目的和发布平台已经清楚。
3. 缺失信息不影响下一步选题或提纲。
4. 用户明确说“先按你的判断来”。

## 问题数量限制

每轮最多追问 3 个问题。问题应按影响程度排序：

1. 目标读者
2. 核心观点
3. 写作目的
4. 内容边界
5. 发布平台
