# 建立六阶段写作工作流快照与 Studio 状态边界

Status: ready-for-agent

## What to build

将 Studio 从由当前浏览位置驱动的八步页面原型，调整为由六阶段写作工作流快照驱动的工作台基础。

作者在 Studio 中看到的正式写作工作流应为捕捉想法、选题生成、大纲规划、撰写初稿、润色改写和文章配图。去 AI 味归入润色改写，排版发布不再作为写作工作流步骤。作者可以浏览工作区，但浏览行为不能把阶段标记为完成或改变写作工作流实例的真实当前阶段。

这一 Ticket 建立后续持久化闭环所需的前端状态边界和工作流快照 Interface：工作流领域状态独立于当前浏览工作区、流程栏偏好与 Toast 等界面状态；流程栏、进度、顶部状态和底部操作栏从阶段状态派生，而不再根据步骤索引或静态演示数据推断。

## Acceptance criteria

- [ ] Studio 只显示六个正式阶段：捕捉想法、选题生成、大纲规划、撰写初稿、润色改写和文章配图；去 AI 味作为润色改写内的能力呈现，排版发布不再出现在写作工作流流程栏。
- [ ] 写作工作流快照能表达每个阶段的草稿、待确认产物、已确认产物、修订信息和阶段状态；阶段状态至少区分等待前置条件、进行中、待确认、已确认、需补充和需检查。
- [ ] Studio 界面状态独立保存当前浏览工作区、流程栏收起偏好和通知；切换浏览工作区不会改变写作工作流实例的真实当前阶段、已确认产物或流程进度。
- [ ] 流程栏和整体进度从各阶段的已确认状态派生，不再根据步骤数组位置将前置步骤自动显示为已完成。
- [ ] 顶部与底部操作显示由阶段状态和可执行动作派生；原有通用“下一步”行为不再承担确认选题、采用写作大纲等业务语义。
- [ ] 现有各阶段工作区在迁移后仍可打开和编辑其演示内容；此次状态重构不要求写作工作流持久化或真实 Agent 产物生成。
- [ ] 为工作流状态模块添加行为测试，覆盖浏览与真实阶段分离、进度派生、阶段状态到可执行动作的映射，以及六阶段流程定义。
- [ ] 现有后端和前端构建、相关测试保持通过；桌面及窄屏下流程栏与当前工作区不产生意外横向溢出。
